CHAPTER 11

Bugs found, gaps left

What broke while making this guide, how each fix works, and what still behaves differently from Bash.

Recording the demo and writing these notes meant running the shell in situations the test suite didn't cover: as a session leader, with a real terminal, and with odd input. Six bugs turned up. Each one is fixed, and the ones that can be tested without a terminal now have tests.

  • fixed

    Startup error as a session leader. Started directly by a terminal emulator, the shell printed setpgid: Operation not permitted. A session leader already leads its group, and POSIX forbids setpgid on it. Now it only calls setpgid when it isn't already the group leader.

  • fixed

    Job numbers skipped. Every foreground command used up a job number, so the first background job after ls was [2]. IDs are now "highest in use + 1", as in Bash. Test: "Job numbering starts at [1]".

  • fixed

    "Stopped" printed twice. After Ctrl+Z, wait_for_job printed the notice and the before-prompt check printed it again. The job is now marked as already reported.

  • fixed

    Demo program optimized away. leak's allocation was deleted by -O2, since it was never read. Now it writes through a volatile pointer.

  • fixed

    Empty pipeline stage crashed. ls | > out.txt parsed, and the child then called execvp(NULL) and segfaulted. Every stage must now have a command. Test in test_parser.c.

  • fixed

    Pipeline exit status. The status came from whichever process was reaped last, so sleep 1 | false reported success. It now comes from the last command, as in Bash. Test: "Pipeline exit status (last command)".

Known differences and rough edges

  • lexer

    echo a2>f is read as echo a plus 2> f, because 2> is treated as an operator anywhere in a word. The fix is to recognise it only at the start of a word.

  • syntax

    No ;, &&, ||, $VAR, $?, globbing (*.c), 2>&1, 2>>, heredocs, or cd ~/dir. A line holding only a redirect (> f) does nothing, where Bash would create the file.

  • jobs

    exit doesn't warn about stopped jobs. Each job has a slot for its own terminal settings (tmodes), but it's never used, so a full-screen program brought back with fg doesn't get its terminal mode restored.

  • errors

    If pipe() fails halfway through a pipeline, children already started are left running and stay in the job table.

  • signals

    The SIGCHLD handler sets a flag nothing reads. That's harmless, because reaping happens before each prompt, but a finished background job is only reported when you next press Enter.

  • tests

    "Monitor termination handling" never actually runs monitor. Interactive job control (Ctrl+Z, terminal hand-off) has no automated tests. Both would need a pseudo-terminal harness like the demo recorder.

  • report

    inspect labels the process state as coming from status, but it's parsed from stat. The value is the same.

What to build next

In the order I'd tackle them: a pseudo-terminal test harness for interactive job control, $? and $VAR expansion, ; && || (which needs a real grammar, a list of pipelines joined by operators), 2>&1, globbing through glob(), and line editing with history, which means putting the terminal into raw mode.

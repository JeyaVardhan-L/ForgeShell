# Unix Signals and Async-Safe Programming

This document explains Unix signals, terminal signal delivery, process disposition, and async-signal safety in ForgeShell.

---

## 1. What is a Signal?

A **signal** is an asynchronous notification sent by the kernel to a process to inform it of an event or request termination.

### Common Signals Managed by ForgeShell

| Signal | Number | Default Action | Origin / Purpose |
|---|---|---|---|
| `SIGINT` | 2 | Terminate | Generated by terminal when user types `Ctrl+C` |
| `SIGQUIT` | 3 | Core Dump | Generated by terminal when user types `Ctrl+\` |
| `SIGKILL` | 9 | Immediate Terminate | Uncatchable, cannot be ignored |
| `SIGTERM` | 15 | Terminate | Standard software termination signal |
| `SIGTSTP` | 20 | Stop / Suspend | Generated by terminal when user types `Ctrl+Z` |
| `SIGCONT` | 18 | Continue | Resumes execution of a stopped process |
| `SIGCHLD` | 17 | Ignore | Sent to parent when a child exits, terminates, or stops |
| `SIGTTIN` | 21 | Stop | Sent when background process attempts to read from terminal |
| `SIGTTOU` | 22 | Stop | Sent when background process attempts to write/ioctl terminal |

---

## 2. Shell Signal Dispositions

A shell process must treat signals very differently from regular user applications:

1. **Ignore Terminal Job Control Signals in Shell**:
   ```c
   signal(SIGINT, SIG_IGN);
   signal(SIGTSTP, SIG_IGN);
   signal(SIGQUIT, SIG_IGN);
   signal(SIGTTIN, SIG_IGN);
   signal(SIGTTOU, SIG_IGN);
   ```
   If the shell did not ignore `SIGINT`, pressing `Ctrl+C` would kill the shell itself instead of interrupting only the active child command.

2. **Restore Defaults in Children**:
   Immediately after `fork()`, the child resets all signals to `SIG_DFL`:
   ```c
   void signals_reset_child(void) {
       signal(SIGINT, SIG_DFL);
       signal(SIGTSTP, SIG_DFL);
       signal(SIGQUIT, SIG_DFL);
       signal(SIGTTIN, SIG_DFL);
       signal(SIGTTOU, SIG_DFL);
       signal(SIGCHLD, SIG_DFL);
   }
   ```
   This ensures standard command utilities (like `grep`, `cat`, or `sleep`) respond to Ctrl+C or Ctrl+Z as intended.

## 3. Async-Signal Safety

Signals can arrive at any arbitrary instruction during execution.
Because the interrupted code may be in the middle of modifying internal data structures or allocating memory:
- **Never call non-reentrant functions inside a signal handler** (e.g. `malloc`, `free`, `printf`).
- Doing so causes catastrophic deadlocks and memory corruption.

### ForgeShell's Safe Approach
ForgeShell handles `SIGCHLD` by doing only async-safe work:
```c
volatile sig_atomic_t g_sigchld_flag = 0;

static void handle_sigchld(int sig) {
    (void)sig;
    g_sigchld_flag = 1;
}
```
Actual process reaping and job notification are deferred to synchronous execution in the main loop (`check_and_notify_jobs()`), ensuring complete thread/reentrancy safety.
